# Changelog

Notable changes to Vulnder. Stack URLs, the JSON feed fields and the Atom feed stay compatible unless an entry says otherwise.

## [Unreleased]

### Added

- **NIS2 and the CRA** (`/nis2`, and docs/NIS2.md): how Vulnder maps, point by point, to the vulnerability monitoring and handling rules in NIS2's Implementing Regulation 2024/2690 (Annex 6.10) and to CRA Article 14's reporting of actively exploited vulnerabilities, with what stays with you. Every page's footer, How it works, the sitemap and llms.txt link to it. It isn't legal advice.
- **A weekly review routine for your AI agent** (docs/agents/nis2-weekly-review.md): it ranks the stack kept in your repository through the MCP server, opens or updates a ticket for each Act now, Attend and out-of-support item with a date to respond by, and writes a dated log with how fresh each data source was. Vulnder keeps no copy.
- **Export for AI ends with a record of the check**: when it ran, when each data source last updated, and a decisions table (owner, action, decided on, done on) with a row for each Act now, Attend and out-of-support item and the date to respond by. It's built in your browser; the only extra request is the data-source status the footer already loads.
- **An MCP server for AI agents** at `/mcp`. Claude Code, Cursor, VS Code, Claude Desktop and other MCP clients can connect with no account or key (`claude mcp add --transport http vulnder https://vulnder.com/mcp`) and use two read-only tools: `rank_stack` ranks a stack in the stack link format, and `rank_cves` ranks up to 2,000 CVE IDs. Answers come from the JSON feed, so they match the site: counts, Fix first, out-of-support and targeted items, and the top results with reasons and fixes, plus links to the full results. It speaks MCP 2026-07-28 and answers 2025-era clients too. New lookups from agents are rate-limited per address in a bucket of their own, so an agent can't use up its owner's browser lookups, and a limited call tells the agent when to retry. Tool arguments aren't logged or stored, and the server calls no model. For self-hosters it needs no new bindings. Setup: docs/AI_AGENTS.md.
- **Check the MCP servers your agent runs.** Drop a `.mcp.json`, `mcp.json` (VS Code, Cursor) or `claude_desktop_config.json` on the home page, or paste one. Servers started with `npx`, `uvx`, `pnpm dlx`, `bunx`, `pipx run`, `docker run` and similar become the npm or PyPI package or container image they run. The file is read in your browser, and its `env` and headers, where API keys live, are never read. Servers that run local code or connect to a remote URL are counted in a note as not checked.
- **AI runtimes and coding agents resolve by name**: Ollama, vLLM, LiteLLM, Open WebUI, Langflow, Flowise, AnythingLLM, text-generation-webui, Cursor and Claude Code now find the CVEs filed under every vendor name their records use. A new home page example describes an AI coding setup.
- **llms.txt explains Vulnder to AI agents**: how to connect to the MCP server, both tools and how to call them well, and what each part of a result means, including that an item with no CVEs may be a key Vulnder doesn't know rather than a safe one.
- **How it works has a three-step guide to using Vulnder from an AI agent**: connect your agent to Vulnder, ask it, and check the agent's own MCP servers, with copy-paste setup for each client.
- **Targeted by attackers.** When CISA has added any of a stack item's CVEs to KEV in the last 90 days, the results page says so above the priorities, with the latest KEV add and whether those CVEs are in your results or affect only versions you don't run, and Fix first marks the item "Targeted". In a backtest over 2025–26, about a third of products with a KEV add got another within 90 days, so patch that product's next advisory within days. A pasted CVE list gets the same for the products its CVEs fall under. Priorities and scores don't change. The JSON feed adds `targeted`, the Atom feed has an entry per targeted item, and Export for AI lists them.
- **Rank a list of CVEs.** A new "By CVE list" tab on the home page takes CVE IDs pasted or dropped from a scanner's report (Nessus, Qualys or Tenable CSV, .nessus XML, Trivy or Grype JSON, or any plain list) and ranks up to 2,000 of them by what to fix first, whatever their age. The report is read in your browser, and only the CVE IDs go into the link. Rejected CVEs are flagged: a duplicate's replacement is ranked in its place, and IDs that aren't published CVEs (reserved, or mistyped) are listed so you can check them. Stack links take the new items as `cve:2021-44228`, alone or beside components, and the JSON feed adds `listed` and `replaces` (see docs/STACK_FORMAT.md). Pasting a CVE list into the stack box offers to move it across. `/#cves` opens the tab.
- **The footer shows how many stack checks Vulnder has served**, once there have been 1,000. Every results load counts, from the site, a shared link or the JSON feed. Atom feed and badge requests don't count. It's one running total, with nothing about the stack or who asked, and it updates every 15 minutes or so. `/api/health` returns it as `checksServed`.
- **A tidier footer.** Each data source is listed once, linked, with when it last updated beside it. "Support dates" are now called "End-of-life dates". The list now folds into one line, "Data sources · all up to date" (or how many are running behind), and opens to a ledger of sources and their ages.
- **Public exploit code raises a CVE's priority.** A reference the CVE record tags "exploit", or a Metasploit auxiliary module, counts as a proof-of-concept exploit (at least Watch). A Metasploit exploit module puts it in Attend. A Nuclei scanner template counts as automatable where CISA hasn't rated it, so with public exploit code it's Attend too. None of these reaches Act now or counts as exploited: only CISA KEV and CISA-reported active exploitation do. Each result says which applied, the JSON feed adds `links.exploit`, and the footer shows when the Metasploit and Nuclei indexes last updated. For self-hosters: apply migration 0010, then run `npm run backfill -- --index-only --exploit-refs --remote` once to fill exploit references for older CVEs (about 44,000 rows). Without the migration, ingest and ranking run as before.
- **CISA Vulnrichment is credited by name** in the footer, About, How it works and the README, as the source of the SSVC assessments behind the priorities. A result with no assessment now says "No CISA Vulnrichment assessment of exploitation, automation or impact yet".
- **For self-hosters: an index of every CVE ever assigned** (migration 0009, table `cve_index`), groundwork for ranking a pasted list of CVEs whatever their age. It holds about 404,000 slim rows. Ingest keeps it current with a few thousand row writes a day, and no table reads beyond one per changed record. On an existing deployment, apply the migration, then run `npm run backfill -- --index-only --remote` once (add `--max-rows 80000` and repeat daily on Workers Free). Without the migration, ingest runs exactly as before and skips the index.

### Changed

- **Clearer MCP answers for agents.** The first line of a `rank_stack` answer now says it covers CVEs new in the window plus the past year's riskiest, and names items with nothing in it, so "0 CVEs" isn't read as "no known CVEs". A `rank_cves` answer says how many IDs were sent and ranked, and names rejected and unpublished IDs. An empty stack gets an error that no longer mentions the feed's `s` parameter.
- **Reading a description no longer fails on a slow AI day.** If the first model hasn't answered within 8 seconds, or fails, Vulnder asks a second one too (Qwen3 30B on Workers AI) and takes whichever answers first. While it reads, the "Reading your stack" circle fills green over the most it can take, then shows a ✓, or a ✗ before the form comes back so you can add items by hand. For self-hosters: set `AI_FALLBACK_MODEL` (empty turns it off). The free-plan default for `PARSE_DAILY_TOTAL` is now 500, down from 600, so even if every parse needs both models it stays inside 10,000 neurons a day.
- **Wider pages on desktop.** Every page now uses a column up to 864px wide (it was 768px), so Fix first rows, badges and tables have more room. Sentences such as summaries and notices still stop at a comfortable reading width.
- **Fix first CVE rows stay on one line.** A long CVE title is clipped with an ellipsis instead of wrapping onto its own line, so every row's priority and ID line up. Hover for the full title; it's also shown in full in the results below.
- **The README, How it works and About match how results are ranked now.** The README lists what Vulnder does (three ways in, Edit stack, the results views, Export for AI), gives the full rules for each priority, and explains the risk score and Fix first. The JSON feed is described as the API behind the results page, which no longer links it.
- **A new home page subheading:** "Someone could be into your stack. See your CVE matches, ranked by what to fix first." It no longer says the ranking is by real-world exploitation alone.
- **About and How it works are shorter and more direct.** About states what Vulnder does, the case against sorting by CVSS, the four priorities with their response times, and the design choices, in tables where that's clearer. How it works now says which sources are fetched hourly and which daily, that exploited and CVSS 7.0+ CVEs are kept for a year, and that out-of-support software ranks with Act now. Its AI, ranking rules, AI assistant and limits sections are tables.
- **The privacy notes say plainly that free text is logged.** Every page now opens its privacy note with "Only free-text entries describing your stack are logged, by Cloudflare's AI Gateway", where before it said the gateway can log them. They also say that files, CVE lists and scan reports are read in the browser and not stored.
- **More free-text parses a day on Workers Paid.** `npm run deploy:paid` now allows 5,000 model parses a day in total, up from 600 (about 65,000 neurons at most). The free-plan default stays 600, and the per-client cap stays 30.
- **For self-hosters: no `workers.dev` or preview URLs.** `wrangler.jsonc` now sets `workers_dev` and `preview_urls` to false, so every request reaches the Worker through your own domain and its zone settings (HSTS, WAF rules). To keep a `workers.dev` address, set both back to true.
- **Fix first no longer repeats the same CVEs for every close match.** A broad name like "Windows" brings in many close matches that share most of their CVEs. Items with exactly the same CVEs now share one row ("+2 more"). When a row holds only close matches, it is headed by the name they share, such as `p:microsoft/windows_server_2025` with "2 close matches", rather than by one of them, so it doesn't read as just Server Core; opening it lists every item it covers. A CVE an earlier row already showed is listed by its linked ID instead of in full. Counts and total risk stay complete. The same applies to the By component and By team views. A note offers Edit stack to remove close matches you don't run. In the stack itself, a close match of a product you also named exactly, at any version, is dropped, since it only repeated that item's CVEs.
- **Results lead with the answer.** The headline comes first, then your stack in one line ("5 items: 4 exact, 1 close match") with the time window and Edit stack, then priorities and Fix first. Long stacks fold their items away. Copy links and the export sit under the headline and again in a "Share and follow" section at the end. The page no longer offers a JSON link; the JSON feed itself is unchanged.
- **Every result says what to do** in plain words: confirm it's yours for a close match, check your version when only the product matched, then upgrade to the fixed version or apply the mitigation. These are the same steps the export gives.
- Each priority shows its **response window** (Act now within 24 hours, Attend within 7 days, Watch within 30 days, Track in your next routine update), and the Attend description now lists everything that puts a CVE there.
- **Exact and close matches are labelled in words**, on the stack and in results, not just with a dashed border. "Product match" is now "Version not confirmed".
- **Act now also catches what's about to be exploited**, not only what already is: a critical bug with EPSS of 10% or more (or NIST LEV of 20% or more), EPSS of 50% or more at any severity, or an edge device (VPN, firewall, gateway) that CISA rates automatable with total impact, which is CISA BOD 26-04's 3-day case for internet-facing systems. These get 3 days, and exploited results still come first with 24 hours.
- **A year-long safety net.** Whatever time window you pick, known-exploited CVEs (CISA KEV or active exploitation), likely-exploited ones (EPSS of 10% or more, or NIST LEV of 20% or more) and CVSS 9.9+ from the last year now show too, marked "Older". Before, they dropped out 90 days after they were published or last changed. A CVE whose EPSS passes 10% after that is fetched again. The JSON feed marks them with `beforeWindow: true`.
- **Tick or untick Edge device** on any product under Edit stack. Tick it for anything the internet can reach directly (a customer portal, an exposed server) to get the same ranking as a VPN or firewall; untick it on a firewall inside your network. The choice is saved in the link as `;edge` or `;internal`. Older deployments reject links that use them.
- **High-severity CVEs are kept for a year.** Ingest now keeps CVEs with CVSS 7.0 or more for a year instead of 90 days, with their affected versions, EPSS history and similar CVEs, so a listed CVE from the last year ranks on its full record (NIST LEV, an exploited similar CVE) rather than the slim index row. Stack results are unchanged: these show only inside the window you pick. For self-hosters, the database grows by about 25,000 CVEs. It builds up as ingest runs; to fill the last year at once, run `npm run backfill -- --remote`.
- **High-severity bugs left unfixed move up as they age.** A CVE with CVSS 8.0 or more that has been public for 60 days is now at least **Attend**, and one with CVSS 7.0 or more at least **Watch**, with the reason "Public for 17 months at CVSS 8.0 or more: a fix is overdue". Older CVEs often have nothing else to go on (CISA assessed them once, and EPSS stays low), so a pasted list of old CVEs no longer leaves an overdue high in Watch or Track. It only raises the priority: risk scores, and every result with exploitation evidence or a prediction, rank as before.
- **No result gets longer than CISA's BOD 26-04 would give it.** A bug CISA rates automatable is now at least **Watch** (was Track when its CVSS was under 8.0). On an edge device, an automatable or total-impact bug is at least **Attend**, and any bug CISA has assessed is at least **Watch**. Each result lifted this way says why.
- **Risk scores agree with the priority.** A critical scores at least as high as a CVE with a 10% EPSS (half that when it needs a login or someone's help), since both put a result in Attend; before, a 9.8 network RCE could score under 1 while EPSS rated it low. A low EPSS score also no longer ranks a CVE below one EPSS hasn't scored yet.
- **One loading checklist from description to results.** "Reading your stack" is now the first step, with a spinner while your description is read, and the same list carries on through the sources instead of a separate screen. Steps tick off a little slower when the answer comes back fast, so you can follow them.
- A **glossary** under the priorities explains KEV, EPSS, LEV, CVSS, the risk scores and the match labels, and results link to how ranking works.
- **Notes about your lookup stay on the page**: names that couldn't be matched, whether items were given teams, and dependencies left out. With no matches, the headline no longer says your stack is clear when some names weren't checked.
- **Errors show next to the form** you're using, not in a line under the page. If the verification check can't run, the page says so and offers adding items by hand, instead of asking you to wait forever.
- "What changed this week" is now "What changed in the last 7 days", since it ignores the time window. Empty priorities are no longer listed in the By priority view.
- The **privacy notes** now say that free text sent to Cloudflare Workers AI can be logged by Cloudflare's AI Gateway in the account running the site. Vulnder itself still stores and logs none of it.
- New tagline: "Someone could be into your stack."
- **About and How it works are shorter and roomier**: tighter copy, short bullets in place of long paragraphs, and more space between sections.
- **Export for AI matches the page.** Fix first rows of merged close matches go by their shared name, and a CVE an earlier row listed is marked "also in a row above" instead of repeated. Similar CVEs in a product sit together. Out of support items are listed first in the instructions, with edge devices marked and the source named (endoflife.date, or the CVE whose vendor called it unsupported). They no longer also show under "Still watched".
- **The daily EPSS refresh downloads FIRST's scores file once** (`epss.empiricalsecurity.com`, about 2.7 MB) instead of about 300 API calls, and reads from D1 only the CVEs whose score moved enough to store. Self-hosters whose ingest has restricted outbound access need to allow that host.
- **Accessibility:** field and button borders now meet 3:1 contrast in both themes. Keyboard focus on "choose a file" is visible. Empty priorities and pending loader steps keep readable contrast. CVE links in the priority tiles and the remove buttons are easier to tap. Start over and Start again move focus and reset the page title. "+N more below" respects reduced motion and moves focus to the results. The How it works diagram scrolls sideways on phones rather than shrinking its labels.
- **Plainer copy on About and How it works**, with fewer slogan labels and staged lines. How it works now links the full ranking rules in RANKING.md; its old README link pointed at a heading that no longer exists.

### Added

- **Out of support.** When you name a release its vendor no longer supports (Windows 7 or 10, Windows Server 2012 R2, Ubuntu 18.04, FortiOS 7.0, an end-of-life router), results open with an Out of support notice: it gets no more security updates, so upgrade urgently. In Fix first it ranks with Act now, whatever its CVEs, and with Attend in the 90 days before support ends. A broad name like "Windows" or "Windows 11" is never flagged. Dates come from endoflife.date, refreshed daily, and hardware it doesn't cover is caught when a CVE's vendor marks the product unsupported. If you pay for extended security updates (ESU, ELS, LTSS, Ubuntu Pro), tick Has ESU under Edit stack, or say so in your description, and it counts as covered until those end; the link carries it as `;esu`, which older deployments reject. The JSON feed adds `support`, and the Atom feed an entry for each finding. "Windows 7" and "RHEL 5" now resolve to that release instead of every newer one as a close match, and "Windows 10 Pro" finds Windows 10.

- **About** (`/about`) and **How it works** (`/how-it-works`) pages: why Vulnder exists, the data pipeline, where AI is used and where code decides, how priorities work, and how to hand results to an AI assistant. Linked from the top right of every page, with a direct "Use it with AI" link, and from the sitemap and `llms.txt`.
- A CVE with no CVSS score whose CNA or GitHub advisory rates it **critical or high** now goes to **Watch** (it was Track), with the reason "Rated critical by its advisory (no CVSS score yet)", and ranks higher within it. A score, when one exists, always decides instead, and a rating alone never reaches Attend. Records pick up the rating as their sources next update them. Needs migration 0007.
- **LEV**, NIST's estimate (CSWP 41) of the chance a CVE has already been exploited, built from its EPSS history. At 20% or more a result goes to **Attend** with the reason "NIST LEV estimate: N% chance it has already been exploited", so a CVE that was hot for weeks and has cooled since stays near the top. It never puts a result in Act now. Results show a LEV badge, and the JSON feed has `evidence.lev`.
- **Similar CVEs** in the same product are grouped into families: one flaw filed twice, variants of one flaw, or a vendor bulletin's batch. The results page folds each family under its highest-ranked member ("+3 similar CVEs in this product"), and nothing is hidden. When a family member is on KEV or actively exploited, the others go to at least **Attend** with the reason "Similar to exploited CVE-… in the same product". The JSON feed adds `family` and `related` to each result. On the free plan, the GitHub Actions token needs Workers AI read and edit for this; without them ingest skips it.
- Each result now shows **which signal decided its priority**, the other reasons, and what data wasn't available (no CISA assessment, no CVSS score, no EPSS score yet), so an unknown doesn't read as safe.
- A suggested **response window** on each result: 24 hours for Act now, 7 days for Attend, 30 days for Watch. It's guidance, based on 2026 time-to-exploit data, not a deadline.
- Act now and Attend results with no fixed version known say **what to do meanwhile**: CISA's required action when it's on KEV, and a link to the advisory.
- The JSON feed adds `why`, `respondWithinHours` and `mitigation` to each result (`reasons` is unchanged), and Atom entries now include the priority, the window and the reasons.
- **Feed passes.** After its Turnstile check, a browser gets a pass (an HttpOnly cookie, no account) that loads 2 different stacks an hour, counted from the first; until the second, the first stack and its other time windows load as often as you like. Once both are used, the browser is locked until the hour is over: nothing loads, including stacks already opened, and the server turns it away from a lock cookie without reading the database. The page greys out Start over, Edit stack, the time window and new lookups, shows a red countdown next to them, and points at it when you click one. A browser with a pass is rate-limited by its pass instead of its IP, so people sharing an office IP no longer limit each other; feed readers, badges and scripts without one keep the per-IP limits. Needs migration 0005.
- A loader, built from the logo, while your stack is read and while matches load. While matches load it ticks off each source it checks (CVE records, GitHub advisories, CISA KEV, EPSS, OSV) and then the exact and close matches. It stays still if your system asks for reduced motion.
- **Export for AI** on the results page saves a Markdown file for an AI agent (or a person) to work through and apply the fixes: every CVE with its priority, risk score, response window, why, exploitation evidence, fixed versions and what to do, plus the fix-first order (with each item's team, when it has one) and instructions. Built in your browser from the page, so it costs no request.
- **Teams for enterprise stacks.** When your description reads as a large organisation's, each item gets the team that usually looks after it (Network, Database, Front-end, Back-end, Platform, Endpoints or Business apps), and results can be grouped **By team** so fixes can be handed out. Jev answers from your description; a fixed table of ecosystems, vendors and product names fills any it leaves open, and the rest are Unassigned, never hidden. Each team keeps the fix-first order, and teams come in the order of their most urgent item. Change a team under Edit stack. The team is written after the item in the link (`p:cisco/ios_xe;network`). Home, small-business and lockfile stacks get no teams.
- **Edge devices** (VPNs, firewalls, gateways and ADCs such as FortiGate, PAN-OS, NetScaler and BIG-IP) are labelled "Edge device" and rank ahead of similar results within their priority, recognised from the product name by fixed code. It never changes a priority and never lowers anything else.
- **CVE summaries** show on every result and change card, with **Expand** to read a long one in full.
- `robots.txt`, `sitemap.xml` and `llms.txt`, and search and link-preview tags on the home page. The footer links to the source on GitHub.

### Security

- Pasted manifests could make the server spend minutes of CPU on one request: a long run of spaces or blank lines, or unclosed tags in a `pom.xml`, made the format detection and the Maven parser quadratic. They now run in linear time.
- A description or manifest repeating one product thousands of times, or naming a product category many times, made one request do millions of comparisons. Each distinct product is now looked up once, repeats share the result, each name is compared only with catalog entries that share its first letters, and a request whose names would match more than 2,000 products is refused.
- Resolving a vendor name ("Cisco", "Microsoft Exchange") now reads only that vendor's top few products from the database instead of all of them, up to 12,000 fewer rows read per request. Needs migration 0006.
- IPv6 clients are rate-limited and counted by their /64 rather than their full address, which one connection can change at will.
- Updated Wrangler to 4.149 for CVE-2026-96889 in `sharp`'s bundled librsvg (development tooling only; the deployed Worker doesn't include it).

### Changed

- Close matches for a misspelt or partial name ("grafanna", "exchange srv") are listed with the most-affected product first, like the close matches for a vendor or a category. Which matches you get is unchanged, and a name now resolves the same whatever else you list alongside it.
- Search engines are told not to index stack links, feeds or badges, so a shared link doesn't put what you run in search results. Only the home page is indexed.
- The manifest upload is now one short line under the examples, inside the form, and the page no longer suggests pasting a manifest into the description box, which has a length limit. Uploads were never held to that limit, and now accept files up to 10 MB (was 5 MB) and 300,000 lines. Only manifest names and text extensions (.json, .txt, .toml, .xml, .lock, .mod, .in) are read, and binary files are refused with a reason.
- The most urgent priority is now labelled **Act now** (was Act). The feed's `priority` value is still `act`.
- CVSS 9.0 or more now puts a result in **Attend** (was Watch), whatever its EPSS. So does an advisory rating a CVE critical before it has a CVSS score. Criticals an attacker can reach over the network without a login or anyone's help rank first within Attend; ones that need local access, a login or someone's help rank after them.
- **Watch** now starts at CVSS 8.0 (was 9.0). Results from 8.0 to 8.9 with no exploit signal move up from Track.
- Results from CVSS 7.0 up say whether an attacker can reach them, for example "Needs a login and user action".
- `GET /api/health` no longer returns record counts. It reports source freshness only and is cached for 15 minutes. Counting the tables read every row in the database on each page load.
- New look: a cooler palette, the Atkinson Hyperlegible typefaces (self-hosted, so no font requests leave the site), and a results page that opens with a strip showing how your matches split across the four priorities.

- Feeds, Atom and badges are kept at the edge for up to an hour (until new data arrives); browsers still keep them for 5 minutes. Each component's CVEs are cached too, so a new stack or window that shares components with an earlier one loads without re-reading them: a Linux kernel stack reads about 2,700 database rows instead of 30,500.
- Stacks touching 1,000 or more CVEs, such as the Linux kernel, are limited to 6 uncached requests a minute per IP (`FEED_HEAVY_LIMITER`); other stacks keep the limit of 60. Self-hosters add the binding from `wrangler.jsonc`.
- `POST /api/resolve` refuses requests that look up more than 200 different products, the most a stack can hold, with HTTP 413.
- The examples on the input page are 2026 stacks: a SaaS app, an AI app, a cloud platform on AWS and an office network. The empty text box shows one of them at random.
- Free-text descriptions are limited to 500 characters (was 2,000), and "Find vulnerabilities" greys out while a description is over it. Longer lists belong in a manifest, which has no such limit.
- Ingest from Node (GitHub Actions on the free plan) assigns similar-CVE families to at most 8,000 CVEs a day, so the first pass stays inside the free plan's D1 writes; `--family-daily` changes it (0 for no cap). The Paid cron has no cap.

### Fixed

- **A stack link can't change meaning when it's shared.** A package item ending in a stray `@` after another `@` (`npm:a@b@c@`) is now rejected as invalid. Before, it was read as a package named `a@b@c` and written back as `npm:a@b@c`, which reads as `a@b` at version `c`. A single trailing `@` (`npm:express@`) still means no version.
- **A double click sends one lookup.** On the CVE list tab, a second click or drop while the first was still being checked could send it again and add a duplicate entry to the browser's history. One lookup now runs at a time, from either tab.
- **Going back to the home page waits for a fresh verification check** rather than using the one from the last visit. That one could have expired, and the lookup was then refused with "verification failed".
- **A results page that failed to load after you'd moved on no longer leaves its error on the new page.** Before, pressing Back while a stack was still loading could show "No answer from Vulnder" under the home form once the load timed out.
- **Common products now find the CVEs filed under their vendor's own names.** CVE records often name a product differently from the short name people use, so several common names matched a key with few or no recent CVEs: "Apache" now finds `apache_software_foundation/apache_http_server` (was `apache/http_server`), and MySQL, MongoDB, Tomcat, Jenkins, Node.js, Grafana, nginx, Exchange and Cisco IOS XE likewise. "Windows 11" now means the Windows 11 releases (about 1,200 CVEs each) rather than the generic `microsoft/windows` (19).
- **Acronyms and everyday names resolve**: RHEL, SLES, ADFS, IIS, OWA, M365, SCCM/MECM, MSSQL, WSUS, AnyConnect, Meraki, EPMM, Pulse Secure, Entra ID / Azure AD, and more. A version picks the product when the vendor files one per version: "RHEL 8" (or "rhel8") is Red Hat Enterprise Linux 8 exactly, "Windows 11 24H2" and "Exchange 2019" likewise. Active Directory, Hyper-V, IIS and WSUS bring in Windows Server, where Microsoft files their CVEs.
- **"Juniper switches" finds Junos**, and categories work for vendors whose CVE records spell them differently: Juniper (`juniper_networks`), Arista, Aruba/HPE, Ubiquiti, TP-Link, Palo Alto Networks, Check Point and others. These are also recognised as network and edge gear for teams and deadlines.
- **No more confidently wrong close matches** for a vendor's name ("MikroTik" no longer suggests MikroORM) or for a category the vendor has nothing in ("Sophos firewall" is now unmatched rather than Sophos Home for macOS). Names known to have nothing in the data yet (Amazon Linux, Rocky Linux) are reported unmatched instead of matching unrelated products.
- **A stuck lookup no longer loads forever.** Results give up after 15 seconds and reading a description after 20, saying Vulnder took too long and offering Try again; a dropped connection says so too. The server stops waiting on the parsing model after 12 seconds (you're offered adding items by hand, as in an outage) and on Jev after 3 (parsing carries on without it). The loading checklist is never ticked off for a request that didn't finish.
- **Pages no longer shrink to a zoomed-out desktop view on phones with a larger font size.** Chrome on Android zooms pages to follow the phone's font setting, which left less room than the page needed: the verification check, the loading screen, long words in CVE summaries and wide badges pushed the page past the screen edge, so Chrome zoomed out and stayed that way on the results. Everything now fits down to 180px wide; the verification check switches to its compact size when there isn't room, and Edit stack rows wrap onto a second line.
- **New CVEs no longer stop arriving when GitHub's API rate limit runs out.** CVE ingest finds the CVE Program's hourly files through the GitHub API; when that is rate limited (for example on shared Cloudflare IPs without a `GITHUB_TOKEN`), it now downloads them directly by release name instead of waiting, sometimes for hours, with CVE records marked stale.
- A manifest with more than 5,000 entries, such as a large monorepo lockfile, no longer fails with "invalid request": the first 5,000 are checked, direct dependencies first, and the results say how many were left out.
- A focus outline no longer frames the whole page after loading or changing view.
- Large stacks no longer fail on the free plan's 50 database queries per request: the feed now reads the biggest stacks in 15.
- The daily EPSS update writes about a third of the database rows it did.
- Ingest is gentler with GitHub and recovers from its hiccups. Calls are spaced at least 250 ms apart. A GitHub 5xx, dropped connection or short secondary rate limit is retried up to twice before the source gives up until the next run. A rejected advisory page token restarts the pass once a run instead of looping. Release listing stops at GitHub's 1,000-release limit instead of failing with HTTP 422. Ingest errors now include GitHub's own message.
- `POST /api/resolve` stops reading a body once it passes 1 MB. Before, a body sent without a `Content-Length` was read in full.
