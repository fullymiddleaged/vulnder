## B. Changes to the brief

1. **Hybrid ingest.** Each module in `src/ingest/sources/*` implements `fetchChanges(cursor)` against an injected `fetch` and uses only Web APIs. A `Store` interface has two implementations: `D1BindingStore` (Worker cron, Paid plan) and `WranglerStore` (Node: generates SQL and runs `wrangler d1 execute --file`, with `--local` or `--remote`). Backfill and the Actions job (`.github/workflows/ingest.yml`, hourly at :17) use `WranglerStore`. The `INGEST_RUNTIME` var picks the mode, and the free-plan wrangler config has no cron trigger. A budget object (subrequests, elapsed time) makes each run stop cleanly and save its cursor, so both runtimes resume the same way. `/api/health` reports staleness, which also covers Actions disabling the schedule after 60 days.
   *Why:* the free plan's 50 subrequests and 10 ms CPU cannot run ingest inside a Worker, and the brief requires a zero-cost deployment.
2. **The CVE source uses the hourly release delta zip, not `delta.json`.** Polling `delta.json` hourly would miss most changes, because it only covers the last ~7 minutes. Find the zips through the releases API, never by building the file name, because tag and asset hours can differ. At day rollover, process the previous day's final zip. Skip records whose `dateUpdated` is at or before the cursor. If ingest falls further behind than release retention, the Node path falls back to `deltaLog.json` (30 days), and beyond that to a re-backfill. The CVE ID regex allows 4 or more digits. *(Revised in phase 1; see D.)*
3. **Retention is defined by activity.** Keep a vuln if it was published in the last 90 days or has any event in the last 90 days, so an old CVE that lands on KEV this week still shows up. Prune everything else.
4. **Manifest parsing runs in the browser.** The shared TypeScript parsers run client-side, and only the extracted `{ecosystem, name, version}` candidates go to the server. A lockfile never leaves the user's machine, and this avoids the 10 ms free-plan CPU limit. `/api/resolve` accepts `{text}` (model path) or `{candidates}` (manifest path). Server-side tests still cover every parser.
5. **Model.** Default `@cf/google/gemma-4-26b-a4b-it`: it is the replacement named in the deprecation notice, its input schema supports `json_schema` with strict mode, and it costs $0.10/$0.30 per M tokens. Estimate ~17 neurons per parse, or ~500 parses a day on the free allowance. Fallback `@cf/meta/llama-3.3-70b-instruct-fp8-fast` (on the JSON-mode list, ~5× the cost, 24k context). The model ID lives in config. Output is validated with zod and discarded if invalid. When the quota runs out, the UI falls back to "add items manually or paste a manifest". Phase 3 re-measures the neuron estimate from a recorded response.
6. **EPSS refresh.** Once a day, after the score `date` advances, batch the in-window CVE IDs (~110 per call, `limit=1000`, ~400 calls a day spread across runs). Write only on a threshold crossing or meaningful change, to stay under 100k rows written a day. EPSS cannot run at all within the free Worker's 50 subrequests, which is another reason for the hybrid design.
7. **KEV** uses a conditional GET (ETag / Last-Modified) and skips the file when it has not changed.
8. **GitHub advisories:** `type=reviewed`, `sort=updated`, `modified>=cursor`, paging through the Link header. Optional `GITHUB_TOKEN` secret, recommended because Workers egress IPs are shared and the 60/h limit is per IP. An ecosystem map converts GitHub names to OSV names (pip → PyPI, rust → crates.io, composer → Packagist, erlang → Hex, and so on).
9. **OSV** returns all-time IDs, which may be PYSEC-, GO- or RUSTSEC- IDs rather than CVEs. Intersect them with D1 ids and aliases. For an unknown ID, call `GET /v1/vulns/{id}` to get its aliases, bounded by the budget and cached. Cache results by (ecosystem, name, version) in the Cache API.
10. **D1 query shape.** Pass lists as one JSON parameter through `json_each()`, because of the 100-parameter cap. Batch statements, because the free plan allows 50 queries per invocation. Index every filtered column, because rows read counts scanned rows.
11. **Rate limiting.** The binding only allows periods of 10 or 60 s and is eventually consistent. The docs advise against keying on IP, but an anonymous endpoint has nothing else to key on. So: a generous IP-keyed limit (the IP is never logged), with Turnstile as the primary gate. Source: [Rate limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

## D. Phase 1 findings (2026-10-04)

Things that behaved differently from the plan, and what the code does about them.

1. **Release asset dates differ from tag dates, and releases are not strictly hourly.** Tag `cve_2026-10-03_2300Z` carries `2026-10-04_delta_CVEs_at_0000Z.zip`, and releases are sometimes 1–2 hours apart. The CVE source indexes releases by asset name and reads the end-of-day zip (`…_delta_CVEs_at_end_of_day.zip`, published around 01:25 UTC) before leaving a day. It waits for that zip rather than moving on, so nothing committed late in the day is skipped. On moving to the next day it re-reads the last hour of the old one, because records committed just after midnight can carry an earlier `dateUpdated`.
2. **No `deltaLog.json` fallback.** The releases list goes back years (6,411 pages at 5 per page), so falling behind release retention is not a realistic case. The source pages back through releases (up to 25 pages, about 90 days) and otherwise fails with "re-run the backfill".
3. **GitHub `/advisories` rejects timestamps with fractional seconds** (HTTP 422 for `modified=>=2026-09-27T18:30:46.972Z`). The URL builder strips them.
4. **GitHub API version:** `X-GitHub-Api-Version: 2026-03-10` is accepted. Ingest pins `2022-11-28`, the version the parsers and fixtures were recorded against. `first_patched_version` is a plain string in current responses; the parser also accepts the older `{identifier}` object.
5. **EPSS accepts `date=` together with a `cve=` list**, so one pass reads a consistent score date. `limit` is set just above the batch size, because the default of 100 is below a full ~110-ID batch.
6. **KEV supports conditional GET** (it returned 304 for a matching ETag), so an unchanged feed costs one request and no writes.
7. **D1 counts every statement in a batch against the per-invocation query limit**, so writes go through `json_each()` with one JSON parameter per statement, chunked to stay under the 100 KB statement limit (which also applies when the Wrangler path inlines the parameter into SQL text).
8. **Budget fairness.** A source that is far behind could spend a whole run's budget and starve the sources after it. Each source now gets a share of what is left (remaining ÷ sources still to run), and unused share rolls over. D1 queries are counted against the budget but never refused, so cursor and status writes still land after a source runs out. The Worker cron caps at 900 to leave headroom under D1's 1,000 queries per invocation.
9. **Measured cost:** with fixture data, a first run uses ~66 subrequests (fetches plus D1 queries) and a caught-up run ~25.
10. **Tooling versions** (checked 2026-10-04): `@cloudflare/vitest-pool-workers` is succeeded by `@cloudflare/vitest-plugin` (1.3.6, used here). It needs vitest ^4.1 (vitest 5 is out but unsupported), and typescript-eslint needs TypeScript <6.1, so TypeScript is 6.0.3 (7.0 is out). npm 10.9's installer crashed on vitest's peer set; npm 11 installed cleanly but blocks install scripts by default, so `allowScripts` in package.json approves only esbuild and workerd. `npm audit`: 0 vulnerabilities.
11. **Workers Logs record request URLs by default.** `observability.redact_query_string: true` strips query strings, so stack URLs (`?s=…`) never reach the logs.
